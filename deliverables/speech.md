# Выступление: PostgreSQL во всех окружениях

## Слайд 1

Я представляю результаты доработки учебного проекта мониторинга государственных программ. В нём рассматриваются жилищная программа и программа развития науки и технологий. Задача состояла в том, чтобы сохранить уже работающую загрузку статистики и сделать следующий шаг: подготовить контейнерное развёртывание, использовать PostgreSQL во всех окружениях, проверить измерение формы собственности и добавить средства анализа. Отдельная часть работы — предложение внутреннего пилота для организации типа Мосстата.

## Слайд 2

В исходных материалах находятся шесть показателей и 6792наблюдения по172территориям и20периодам. Это опубликованные статистические величины, а не плановые проценты выполнения программ. Оригинальные файлы сохраняются неизменными. Новому пользователю достаточно скачать репозиторий: рабочая база в поставку не входит. Первоначальные записи загружаются из SDMX в чистую PostgreSQL. Метаданные объясняют смысл показателя, единицу, период и организацию-источник.

## Слайд 3

Итоговая схема начинается с опубликованной выгрузки ЕМИСС. Загрузчик проверяет архив, формат XML, периоды и измерения. Наблюдения и связи попадают в PostgreSQL, а исходные файлы сохраняются отдельно по контрольной сумме. Django предоставляет внутренний интерфейс, таблицу, графики, CSV и API чтения. Каждое наблюдение связано с источником и импортом. Поэтому полученное число можно сопоставить с исходным файлом, а не воспринимать как значение неизвестного происхождения.

## Слайд 4

В Compose выделены база данных, одноразовый шаг миграций и приложение. Миграции должны завершиться до обслуживания запросов. Для приложения выбран Gunicorn, для статики используется WhiteNoise. Процесс работает без root, параметры и секреты передаются через окружение. Порт базы наружу не публикуется, данные и XML сохраняются в постоянных томах. Сборка, миграции и готовность сервисов проверены в GitHub Actions на Linux. На локальном компьютере Docker отсутствует.

## Слайд 5

Перед удалением прежнего режима существующие данные были однократно сохранены в PostgreSQL. Перенос охватил реальные строки, а не заменил их чтением исходных XML. Сверялись справочники, изменения метаданных, история импорта, связи и последовательности. Резервная копия и дамп хранятся вне Git. Затем сохранённая PostgreSQL обновлена новой миграцией. Все строки до и после совпали с учётом изменения представления числового поля. Исходные копии не перезаписывались.

## Слайд 6

Действующая модель использует обычный DecimalField и NUMERIC с80значащими разрядами, из которых30дробные. Это явно документированная точность. Преобразования через float нет. Импорт отклоняет превышение точности. Перед обновлением базы миграция проверяет, что изменение типа не округлит существующие значения. Если проверка не проходит, операция останавливается. Старый класс поля сохранён только для исторической миграции и больше не используется рабочей моделью.

## Слайд 7

Единый порядок запуска одинаков на Windows и Linux. Пользователь создаёт собственные секреты, поднимает Compose, явно выполняет bootstrap_postgres с флагом загрузки данных и создаёт администратора. При обычном перезапуске данные не импортируются. Повторная явная загрузка не создаёт дубликатов и сохраняет ручные правки метаданных. Windows BAT служит только обёрткой над Compose. При отсутствующей конфигурации PostgreSQL приложение выдаёт ошибку, другую базу автоматически не создаёт.

## Слайд 8

Независимо исследованы все шесть XML. ОКФС присутствует только в показателе 44198. В наблюдениях используются четыре кода: федеральная собственность, собственность субъектов, муниципальная собственность и итог 200. Код 199 есть в справочнике, но записей по нему нет. Поэтому он не превращается в нулевую категорию. Коды 199 и 200 сохраняются раздельно. Кроме того, приложение различает неприменимое измерение, пропуск, неизвестный код и известное значение. Неизвестный код сохраняется с диагностикой.



Особенность этого показателя заключается в кварталах. Поле Time содержит год, а квартал задан атрибутом PERIOD. Если оставить только территорию, ОКФС и год, получится четыреста девять групп с несколькими записями. После учёта квартала совпадений нет. Контрольный ряд России за 2014 год при ОКФС 200 содержит 111,7, 120,3 и 125 процентов. В исходной базе кварталы уже сохранялись. Доработка добавила явный контроль противоречий между двумя способами задания периода.

## Слайд 9

Добавлены три диаграммы. Соединённые точки показывают изменение между периодами: в нашем контрольном примере рост составляет 13,3 процентного пункта. Диаграмма рассеяния сопоставляет два показателя по одним территориям и одному периоду. Связь на ней не означает причинность. Диаграмма размаха показывает медиану, квартили и выбросы. В примере пяти субъектов за 2020 год медиана ввода жилья равна 1,2 миллиона квадратных метров. Все три набора используют общую выборку с таблицей и CSV. Пропуски не заменяются нулями, разные уровни территорий и категории ОКФС не смешиваются.

## Слайд 10

На PostgreSQL прошли все54актуальных теста без пропусков. Проверяются чистые миграции, обновление существующей базы, точность, повторный импорт, состояния ОКФС, кварталы, общие фильтры и права доступа. Тестовая база отделена от рабочей. Специальная тестовая роль имеет право создавать тестовые базы только в отдельном окружении. Рабочей роли такое право не предоставляется. GitHub Actions дополнительно проверяет Compose, загрузку6792строк, восстановление и пересоздание контейнеров.

## Слайд 11

Резервирование охватывает PostgreSQL и исходные XML. Приложение кратко останавливается для согласованной копии, затем возвращается к работе. Восстановление выполняется в отдельную базу и сопровождается сравнением fingerprints. Перезапуск сервера проверен отдельно. Тома при штатном обновлении не удаляются. Откат требует совместимой версии кода и согласованных данных. Браузерная проверка отрисовки canvas и скачивания PNG в этой среде отдельно не выполнялась.

## Слайд 12

Для организации типа Мосстата предлагается пилот внутреннего аналитического модуля. Оператор получает опубликованную выгрузку, проверяет её и фиксирует импорт. Аналитик формирует сопоставимую выборку и экспортирует результат для отчёта. Администратор управляет ролями и сопровождением. Официальные источники подтверждают назначение Мосстата и открытый доступ ЕМИСС к показателям и метаданным. Они не подтверждают нашу интеграцию с внутренними системами. Размещение, корпоративная авторизация и критерии приёмки должны согласовываться отдельно. Внедрение в Мосстате не заявляется.
