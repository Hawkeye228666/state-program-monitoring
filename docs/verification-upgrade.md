- Django check: ошибок нет; makemigrations --check --dry-run: изменений нет; collectstatic успешно завершён.
- Независимый audit_okfs всех шести оригинальных XML: 6792 строки; 44198=1226; коды12/13/14/200=536/128/13/549; 199 отсутствует в наблюдениях. 409 групп без квартала и 0 с кварталом; контрольные значения111.7/120.3/125 подтверждены.
- Тестовый клиент с настоящей авторизацией и CSRF: вход, предпросмотр общего ZIP, подтверждение повторного импорта6792 без дубликатов, фильтры, dumbbell/boxplot, CSV, выход. Запрет загрузки для аналитика, отказ анонимному API, права оператора и администратора проверены.
- Точные числа/пропуски, ОКФС отсутствующий/пропущенный/неизвестный/известный,199/200, фильтр/таблица/CSV/JSON, сопоставимость scatter, R-7/1.5IQR boxplot, изменения в п.п., PNG-кнопки и JS syntax проверены кодом/тестами. Скачивание PNG в реальном браузере не проверено.
- Проверены bootstrap_local без интерактивного ввода, поиск Python в BAT --detect и защита create_env от перезаписи. Полная установка нового venv двойным щелчком отдельно не выполнялась.
- Все6файлов data/sources совпадают SHA256 с исходной SQLite; оригинальныеDOCX/ZIP не менялись. SDMX/XML/DOCX помечены binary в Git, чтобы преобразование CRLF не меняло оригиналы.

## PostgreSQL и контейнеры

Выполнены проверки настоящего PostgreSQL17.11, CPython3.12.14, Django5.2.19: все58тестов прошли за33,899с без пропусков; протоколы pg-verification.json и pg-verification.log. Проверены перенос реальных6792строк, источников, сверка всех полей, FK/последовательностей, pg_dump/pg_restore в отдельную БД, повторный импорт и перезапуск PostgreSQL. Это не заменяет контейнерную проверку. Дополнительная копия SQLite с тестовым пользователем сохранила password hash, группы/права, правку метаданных, историю с оператором и точное UTC-время. Последовательности проверены реальными вставками. Сервер PostgreSQL после проверок остановлен.

Docker CLI/Engine на локальном Windows-хосте не обнаружены. Эти проверки фактически выполнены в GitHub Actions на Ubuntu24.04: сборка образа, docker compose config/up --build --wait, готовность, перенос6792строк, backup/restore в отдельную БД и совпадение fingerprints до/после force-recreate. Оба задания compose/postgresql успешны. PostgreSQL в CI:58тестов за31,598с, без пропусков. Протоколы: ci-verification.json, ci-compose.log, ci-postgresql.log. При разборе логов обнаружен неиспользуемый control socket Gunicorn в read-only каталоге; он отключён, дополнительный прогон проверяет чистый старт, UID10001 и HTTP-выдачу статики.

## Ограничение проверки интерфейса

Встроенный браузер не смог подключиться к localhost из изолированной среды (ERR_CONNECTION_REFUSED/ERR_CONNECTION_TIMED_OUT). Управление локальным Chrome остановлено Computer Use: не удалось достаточно надёжно определить текущий URL для применения политики. Дальнейшая автоматизация интерфейса прекращена.

Поэтому реальных скриншотов приложения и фактической браузерной проверки canvas/PNG нет. Сохранены реальные HTML-ответы Django с исходными данными для локального просмотра; они не называются скриншотами и не доказывают успешный браузерный пользовательский сценарий. Серверный сценарий проверен тестовым клиентом отдельно.
